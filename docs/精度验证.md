# 视频主计时的精度门槛与配置档

## 发布状态

0.4.0未附带任何真实通过配置，自动视频确认关闭。自动化测试用合成配置仅在临时目录构造，不进入安装包或真实数据库。软件数值测试不代表人体判定正确，也不代表端到端精度。

主计时参考当前 USB 回调主机单调时刻，经过实测USB延迟校正。手机帧时钟通过签名往返样本映射至主机时钟，并扣除经过实测的相机链路延迟。保留原始Timy3起跑设备时间，不直接与手机时钟相减。帧处理和网络到达时刻均不是过线时刻，录像按钮时刻加文件PTS不被采用。

## 采样要求

每个拟自动确认的完整配置至少100次独立、可追溯的比较，最大绝对误差≤10ms。覆盖正常Wi-Fi、拥堵、长时间与漂移、掉帧，另测系统时间调整、页面重载、电脑重启、USB接入波动。报告有符号偏差、P95绝对误差、最大绝对误差、样本数、原始数据及参考不确定度。只挑部分成功样本无效。

共同参考必须确实对应胸腹躯干前缘触及终点平面。手臂先遮挡光电门的时间不是该真值。可使用独立可追溯参考计时及独立影像人工标注完成比对；现场工作流仍保持Wi-Fi软件同步，不新增同步灯等设备。参考方法由现场验证人员说明和审核。

视觉标注集需覆盖手脚先到、前倾、反向、停留、重复进出、紧贴、遮挡、模糊、逆光和轨迹交叉，分别报告漏检、误检、重复与人工复核率。手机高帧率请求不代表实际获得。30/60fps或分析跟不上而缺关键帧时，必须按实测和配置门槛保持待核验。

## 配置格式

选中实际视频候选后，可点「导出所选候选配置草稿」，自动带入本机、手机、模式、模型和帧时钟标识。草稿未验证、没有测量样本，不能开启自动确认。填入真实测量、人工审核后，通过本机复核页导入JSON，不接受网页创建/修改配置。以下字段说明不包含伪造测量样本，不可直接作为通过配置：

```json
{
 "id":"现场审核后分配的新唯一标识",
 "rigFingerprint":"电脑复核页给出的USB/SDK/系统配置标识",
 "captureFingerprint":"录像登记中实际手机/浏览器/相机/模式/适配器字符串",
 "modelVersion":"bodypix-2.2.1-m075-s8-q2-torso-v1",
 "clockSource":"rvfc-captureTime",
 "settingsJson":"与该组实际冻结VisionSettings按协议序列化的完全相同JSON字符串",
 "referenceDescription":"参考器材、可追溯关系、躯干标注方法及测量条件",
 "reviewedBy":"审核人员",
 "realMeasurements":false,
 "usbDelayCorrectionUs":0,
 "cameraDelayCorrectionUs":0,
 "maxRttUs":5000,
 "maxJitterUs":2000,
 "maxClockAgeUs":5000000,
 "maxFrameGapUs":10000,
 "minimumConfidence":0.8,
 "allowManualStart":false,
 "measurements":[]
}
```

每条真实 measurements：id、condition(normal/congested/long/frame-gap)、estimatedUs、referenceUs、referenceUncertaintyUs、evidence(原始记录标识/路径及可追溯说明)。至少100条，referenceUncertaintyUs≤1000，全部误差≤10000。两项校正必须根据独立实测确定，不能调到让视频与手臂触发的光电门差值为零。

`python scripts/report-camera-validation.py actual-profile.json --output actual-report.json` 计算偏差、P95、最大绝对误差和数值检查结果；工具不生成数据，也不能证明实测真实性。现场核对原始记录、机型/OS/浏览器、采集模式、帧时钟、模型、机位、USB连接及运行条件后再导入。不同配置不得共用未经验证的校正。

导入通过配置也不保证每个事件通过：当前时钟、间隔、置信度、完整证据、唯一原片帧对应和人工更正情况仍分别核验。原片匹配不唯一时保留候选。人工选新帧若缺有效采集时钟映射，不从PTS补算，须进一步验证或由裁判启用备份。

## 后续现场验收

至少苹果Safari、安卓Chrome各一台真机，且每个宣称支持配置单独完成100次测量；连续50人次检查绑定、录像恢复、复核、来源切换、排名和导出。只有证据支持的完整配置才可开启视频自动确认。手动起跑/STOP仍含人为反应误差，独立注明。
