# 0.5.0 软件缺陷验证记录

日期：2026-10-30。范围是软件回归；本轮没有连接真实 Timy3 或手机，没有迁移用户比赛数据。

## 已复现并修复

| 问题 | 修复及回归证据 |
|---|---|
| 已过线轨迹吸附后续同路选手 | 旧算法连续100次只保留2次；限定失联生命周期、距离与方向连续性，已完成轨迹不抢占新接近轨迹。新增100次连续、紧跟、同帧多人、停留/长间隔测试；身份混淆保留待复核 |
| 检测缓冲区积压 | 保留 Worker 就绪再取最新帧；实际延迟1.2秒推理时队列≤1，原片继续录制 |
| 模型失败后不能恢复/旧回调污染 | 请求、Worker 实例和分析会话分开校验；30秒加载、10秒单帧超时；两次自动重试后暂停，手动重试恢复，同组原片不重建 |
| 文件 PTS 被误当有效计时 | 补检/人工候选显式 clock:null，用时留空；接口拒绝补检伪造实时钟，不覆盖既有来源/成绩 |
| 分片 MP4 尾帧索引漂移 | 已复现补检停在101/103帧；保留每片 tfdt 真实边界，避免上一片估计时长抹平间隔。原片全程补检、续检与重复扫描通过 |
| 仅视频组正常停录被判提前结束 | 旧判断只认已确认成绩或C1；现将已采集视频候选用于停录提示，不作为成绩确认。停录待确认与已知证据不完整分开保存 |
| DNS/DNF/DSQ 被异步操作恢复、状态把真终点当误按 | 保护状态，释放绑定而不改原始事件性质；迟到证据、解绑、复评组合均不能恢复选手，必须裁判明确恢复 |
| 来源重复操作追加成绩 | 相同有效来源、重复状态幂等；来源切换、绑定与更正按同一 SQLite 事务提交，保留历史及失败回滚 |
| 结束旧组后立即下一组漏停/停错 | 按组次和原片保留停录请求，允许结束后的首次原片登记；手机保存确认独立回报。连续50组与旧组确认晚到回归通过 |
| 心跳重建列表影响选择与输入 | 未改变的列表保留对象，更新时按标识恢复选择；WPF 自动化400次刷新保留选择、原因和光标，按钮按状态启用 |
| 原片/解码阻塞新结果、失败无限重试 | 小型证据、原片和核验分别调度；超时与退避；401/403等待配对，409保留冲突，不改不可变请求。原片完成与帧核验分别显示 |
| 实时帧和原片核验尺寸不同 | 保存实际分析尺寸及 dhash256-v1 版本，原片解码使用相同几何尺寸；不猜测帧对应 |

## 交付与尚未验收

交付0.5.0独立 Windows 安装包、带网页和本地模型的便携程序、源码包、操作及迁移说明。旧便携目录保留；没有执行真实实例安装或回滚。安装器编译验证不等于真实用户机器升级演练。

没有真实达标配置，**视频自动确认仍关闭**；光电备份仍需裁判匹配号码、填写原因并明确启用。原片补检只生成待复核候选，文件时间不会产生正式成绩。

尚未完成：苹果 Safari/安卓 Chrome 真机相机与恢复、真实长原片兼容、现场多人和不同光线标注集、连续50人次现场验收、每套完整配置100次可追溯端到端比较及最大绝对误差≤10ms。软件模拟通过不能代替这些现场与精度验收。
