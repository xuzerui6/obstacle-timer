# 0.5.0 升级、数据兼容与回滚

本版协议 v4、SQLite v4、手机 IndexedDB v3。升级须等比赛、录像和后台补传空闲后进行；没有自动部署或强制刷新正在录像的页面。

## 安装

1. 结束本组、确认手机原片已保存。保留手机网页及其浏览器数据；可另外导出重要原片。
2. 主动退出电脑计时程序，再运行 `ObstacleTimer-Setup-0.5.0-win-x64.exe`。安装器检测到旧程序运行时会拒绝升级，不结束它。
3. 如果原来通过安装器安装，覆盖程序文件前将旧程序目录复制到 `%LOCALAPPDATA%\ObstacleTimer\release-backups\日期时间`。备份失败则停止升级。便携版构建输出改为 `artifacts/windows-0.5.0`，不会覆盖旧的 `artifacts/windows`。
4. 启动新版后，电脑和手机均应显示 **0.5.0**。手机在空闲时刷新，并按提示重新扫码。保持原来的 HTTPS 地址和浏览器；浏览器会按网站来源隔离数据，改用另一地址不会自动搬运原片。
5. 重新配对只恢复授权，不删除原片、候选、分片或补传队列。版本不同时提示更新；录像中不提供强制刷新操作。

本轮只构建与模拟测试，没有启动真实 USB 桥、迁移用户比赛数据库或安装覆盖用户实例。

## 数据迁移

| 数据 | 行为 |
|---|---|
| SQLite v1/v2/v3 | 修改数据库前通过 SQLite Backup API 生成 `timing.pre-v4-时间.sqlite`，覆盖 WAL 中已提交数据；然后升级至 v4 |
| 历史成绩 | 保留原计时来源、未舍入值、成绩版本、原始报文、号码绑定及更正历史，不变成视频主成绩 |
| 旧视频候选 | 接受旧实时提交格式；旧模型、缺少分析尺寸、旧时钟会话等证据不足时保持待核验 |
| 手机 IndexedDB v1/v2 | 原库 `obstacle-finish-v1` 原位升级至 v3，新增 `analysisJobs`；保留 clips/chunks/outbox/vision |
| 配置档 | 新检测模型和帧时钟/USB 接入指纹与旧版不同；旧精度配置不能使本版自动确认。不附送任何模拟达标配置 |
| 未完成补传 | 断点与 SHA256 校验沿用；认证失效暂停并要求扫码，409 冲突保留不可变本机记录，不反复覆盖服务器 |

数据库版本高于本程序支持版本时拒绝打开。升级失败不删除已有文件。原片的「已传完整」与「帧对应已核验」分别保存；后者失败可手动重新核验。

## 回滚

退出新版后使用旧程序目录备份或原 0.4.1 安装包。旧版不能直接打开 v4 数据库；应将升级前 `timing.pre-v4-*.sqlite` 复制到**另一个数据目录**，以旧程序的 `--data` 参数打开核对。先另外备份当前整个数据目录，不覆盖 v4 比赛记录或旧备份。升级后新产生的成绩、证据和分片不能通过旧数据库自动回迁，须保留新版与导出记录。

不要删除浏览器网站数据，也不要将本机证书私钥、真实比赛数据库或运动员原片上传到公开仓库。源码包和 GitHub 不包含这些内容。
